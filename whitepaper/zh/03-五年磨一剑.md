# 第二章 矩阵起源：五年磨一剑

Agent Runtime 需要一个"数据库内核级的版本控制底座"。这个判断并非事后追认的口号——它是矩阵起源过去五年技术积累自然汇聚的结果。让我们回过头来看，这五年我们做了什么。

## 2.1 2020–2023：构建数据库内核

矩阵起源从 2021 年开始开源构建 **MatrixOne**，一个云原生的 HTAP 数据库。我们做了几个关键的架构选择。当时，这些选择是为了做一个更好的数据库；但今天回头看，它们恰好为 AI 基础设施埋下了最重要的伏笔。

- **不可变存储（Immutable Storage）。** 数据以不可变对象的形式存储在 S3 兼容的对象存储上。一旦写入，对象不会被修改，删除通过墓碑记录实现。这意味着——**历史数据天然保留，任何时间点的状态都可以被引用。**

- **MVCC（多版本并发控制）。** 每个事务看到数据库的一个一致快照，所有修改先在独立的工作空间中进行，提交时原子生效。这意味着——**隔离是天然的。**

- **存算分离（Storage-Compute Separation）。** 计算节点（CN）和存储层（S3）完全分离，计算节点可以无限水平扩展。这意味着——**版本控制操作不会影响生产负载。**

- **LSM 树结构。** 数据按主键组织成 LSM 树，变更以增量对象的形式追加。这意味着——**两个版本之间的差异天然就是增量对象的集合，diff 不需要全表扫描。**

这四个看似纯粹"数据库工程"的选择，在 2024 年汇聚成了一个关键能力：**数据库内核级的版本控制。**

## 2.2 2024：Git for Data

2024 年，我们在 MatrixOne 内核中实现了完整的数据版本控制系统。这不是一个外挂的工具，而是利用上述架构特性**原生实现**的能力。它把软件工程里被验证了三十年的 Git 范式，第一次以生产级的性能带到了 TB 级结构化数据上：

- **snapshot（快照）**：记录表在某个时间点的状态，本质上就是元数据目录的一个引用。
- **clone（克隆）**：零拷贝创建表的副本，只复制元数据目录结构——**0.2 秒完成，仅占用 314KB**。
- **diff（比较）**：只扫描两个版本之间的增量对象，而不是全表——**6 亿行表的 diff 只需 3 秒**。
- **merge（合并）**：三路合并，自动区分真冲突和假冲突，原子性提交——**100 万行变更的 merge 只需 16 秒**。
- **revert（回滚）**：恢复到任意历史快照。

我们把这套系统的设计与实验结果，发表在论文 **《Version Control System for Data with MatrixOne》（arXiv:2604.03927）** 中。在 TPC-H 100GB 数据集（6 亿行）上，**内置版本控制操作比等价的 SQL 实现快 100–500 倍**。

当时，我们的目标是服务数据工程师——让他们像使用 Git 一样管理数据。但很快我们意识到，这套原语的价值远不止于此：**它正是 Agent Runtime 所缺失的那块地基。**

## 2.3 2025：数据平台 MOI 与记忆层 Memoria

2025 年，我们在 MatrixOne 之上构建了两个关键产品，并在 9 月于上海的战略产品发布会上正式发布。它们分别对应 Agent 的"认知"与"记忆"两大需求。

### MOI（MatrixOne Intelligence）：Agent 认知世界的接口

MOI 是一个 **AI 原生的数据智能平台**，定位为企业的下一代 Data Infrastructure，技术对标 Databricks + Snowflake。它让 AI Agent 能够通过自然语言，理解并操作结构化的业务数据：

- **NL2SQL**：将自然语言转化为精确的数据库查询；
- **语义层（Semantic Layer）**：提供业务概念到数据结构的映射，让 Agent 理解"客户""信用等级""毛利率"这些业务语言；
- **RAG 与 Agent 能力**：让数据分析变得自然而智能。

同时，MOI 把企业分散、异构的多模态数据（文档、图片、音视频）统一接入、AI 原生解析、治理为可检索的可信知识——这部分能力将在第四章详细展开。一句话：**MOI 是 Agent 认知世界的接口，是 Agent 的"数据库"。**

### Memoria：Agent 积累经验的机制

Memoria 是一个**开源的 AI Agent 记忆层**。它为 Agent 提供跨会话的持久化记忆——存储、检索和更新。

关键差异在于：**Memoria 构建在 MatrixOne 之上，直接复用了数据库的版本控制能力。** 记忆不再是简单的追加写入，而是可以被**分支、比较、合并和回滚的版本化数据**。一个 Agent 可以在自己的记忆分支上安全地试验，验证无误后再合并回主线；当两个 Agent 对同一事实产生矛盾认知时，系统能自动检测冲突、隔离低置信度记忆，交由人类或上级 Agent 仲裁。一句话：**Memoria 是 Agent 的"内存"，是它积累经验、持续进化的机制。**

---

到这里，一个完整的图景开始浮现：**数据库内核（地基）→ 版本控制原语（核心能力）→ MOI 数据平台 + Memoria 记忆层（双支柱）。** 它们不是几个独立系统的拼凑，而是从内核到应用层一以贯之、共享同一套版本控制基础设施的整体架构。下一章，我们把这张全景图完整地铺开。
