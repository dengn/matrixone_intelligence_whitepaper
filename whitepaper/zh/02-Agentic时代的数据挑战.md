# 第一章 Agentic 时代的数据挑战

## 1.1 从"会思考"到"能干活"：Agent 元年的到来

要理解 Agent 时代对数据底座提出的全新要求，首先要理解 Agent 与上一代 GenAI 应用的本质区别。

驱动 GenAI 的核心是大语言模型（LLM）。它本质上是用计算机构建巨大的神经网络结构来模拟人脑神经元，再将海量知识压缩进庞大的参数之中。这赋予了计算机一种全新的"类人脑计算能力"——能够理解人类的语言和意图，并生成便于人类理解的内容。这与传统计算机擅长的高速、精确数学计算有着根本区别：传统计算精于确定性运算却难以理解自然语言，而 GenAI 长于语义理解与创造却天生不擅长精确计算。两者共同构成了当今 IT 世界的新型计算基座。

而 **AI Agent（智能体）** 则是在大模型这颗"大脑"之上的又一次跃迁。一个完整的 Agent，通常由以下几个要素构成：

- **大模型（推理内核）**：负责理解、规划与决策；
- **工具调用（行动能力）**：通过 API、数据库、检索、代码执行等手段与外部世界交互；
- **记忆（Memory）**：跨会话保留偏好、事实、决策与历史，使 Agent 能够"积累经验"；
- **上下文（Context）**：在每一次决策时，被动态供给与当前任务相关的、最新的、可信的信息；
- **自主循环（Autonomy）**：感知 → 规划 → 行动 → 反思的连续闭环，直至任务完成。

换言之，GenAI 解决的是"**给定输入、生成一次输出**"的问题；而 Agent 解决的是"**给定目标、自主完成一连串带状态的任务**"的问题。这一字之差，对底层数据基础设施提出了天壤之别的要求——从"一次性喂数据"，变成了"持续供给可信上下文与记忆"。

## 1.2 风口下的"死亡鸿沟"

2026 年被广泛称为"Agent 落地元年"。资本与企业的热情空前高涨：

- Gartner 预测，到 **2026 年底，40% 的企业应用将内置任务型 AI Agent**，而 2025 年这一比例还不到 5%；
- 在 **2026 年 Q1** 新发布或更新的企业应用中，已有 **80%** 至少内置了一个 AI Agent（2024 年仅为 33%）；
- 全球 AI Agent 市场规模 2026 年预计达 **百亿美元** 量级，至 2030 年年复合增长率高达 **44%–46%**；
- 在最乐观的情景下，Agentic AI 到 2035 年可驱动约 **30%** 的企业应用软件收入，对应规模超过 **4500 亿美元**。

然而，热度与落地之间横亘着一道巨大的鸿沟。Gartner 同时给出警示：**到 2027 年，超过 40% 的 Agentic AI 项目将被取消。** 主要原因包括：

1. **成本失控**：分散的数据栈、重复的数据搬迁与治理投入，使 Agent 的运行与维护成本居高不下；
2. **商业价值不清晰**：Demo 惊艳、生产拉胯，无法稳定产出可量化的业务收益；
3. **风险与治理无法落地**：Agent 自主行动带来的可追溯性、可审计性、合规性难题悬而未决；
4. **数据没有准备好**：这是最根本、也最被低估的一条。当前仅有约 **17%** 的组织真正部署了 AI Agent，超过 **60%** 仍在观望或试验，而横在他们面前最大的拦路虎，正是"数据未就绪"。

一个被行业反复验证的结论是：**Agent 落地的瓶颈，已经不在模型，而在数据。** 到 2027 年，凡是不优先建设高质量 AI-Ready 数据底座的企业，都将难以规模化地推进 GenAI 与 Agentic 应用。

## 1.3 瓶颈转移：从模型能力到数据、上下文与记忆

为什么是数据？因为通用大模型的能力正在快速"平权"。当人人都能调用同样强大的基座模型时，模型本身不再是差异化的来源。真正决定 Agent 在你的企业里好不好用的，是它能否被持续供给**符合你业务场景的、可信的、最新的上下文与记忆**。

这催生了一门正在成为核心学科的新工程实践——**上下文工程（Context Engineering）**。它关注的核心问题是：

- Agent 在每一次决策时，应该"看见"哪些数据源？
- 它依赖的知识库是否是最新的、被治理过的、可信的？
- 单轮上下文窗口有限，应该检索什么、何时检索、检索多少？
- 跨越多轮、多会话乃至多个 Agent，状态与记忆如何持久、如何同步、如何不互相矛盾？

如果说过去两年的关键词是"提示词工程（Prompt Engineering）"，那么 Agent 时代的关键词就是"上下文工程"。而上下文工程的成败，最终取决于底层是否有一个**统一、可信、带版本、带记忆**的数据底座。模型再聪明，喂给它的若是碎片化、过时、自相矛盾的"脏上下文"，只会成倍放大幻觉、加剧错误。

## 1.4 为什么传统数据栈喂不饱 Agent

绝大多数企业今天的数据架构，是为"人用的 BI 报表"和"传统在线业务"设计的，而非为"Agent 自主消费"设计的。当我们试图把一个 Agent 接入这样的栈时，会立刻撞上五道墙：

### 严重的数据碎片化

为了支撑 Agent，企业往往需要同时整合结构化（业务库）、半结构化（JSON/日志）和非结构化（文档、图片、音视频）数据。这些数据分散在关系库、NoSQL、对象存储、云盘、IM 工具、业务系统乃至个人设备中，物理位置分散、格式高度异构。传统做法是用 MySQL + Elasticsearch + ClickHouse + 专用向量库 + 对象存储 + 一堆 ETL 管道拼装起来——组件越多，数据孤岛越深，链路越长，一致性越难保证。Agent 在这样的架构上"取数"，如同在迷宫里找钥匙。

### 无版本、无审计

Agent 是自主行动的。它读了什么数据、基于哪个版本的知识做了决策、产生了什么后果——这一切如果不可追溯、不可回溯、不可审计，企业就根本不敢把关键业务交给它。然而传统数据栈天生缺乏对"数据版本"的一等公民支持：你无法轻易地把数据回退到上周二的状态，无法为一次危险的实验开一个隔离分支，更无法为每一次数据变更留下不可篡改的完整审计链。在金融、政务、医疗等强合规行业，这是 Agent 落地的硬门槛。

### 无记忆：会话即遗忘

这是 Agent 区别于传统应用最致命的一点。一个没有记忆底座的 Agent，每开启一个新会话就"失忆"一次：它记不住用户的长期偏好，记不住上个项目的关键决策，记不住自己曾经犯过的错。更糟糕的是，当不同来源的信息发生冲突时，它无法识别矛盾、无法隔离低置信度的"脏记忆"，只能照单全收，最终在长期交互中不断自相矛盾、积累幻觉。传统的"向量库 + RAG"只能解决"检索外部知识"，却解决不了"Agent 自身的、可演进、可审计的长期记忆"。

### 多模态治理门槛高

Agent 要消费的远不止文本。一份 PDF 的处理链路就包括版面检测、分块、文字/表格/图片识别、特征抽取；图片、音频、视频还需要 OCR、ASR、抽帧等额外环节。每种格式都涉及复杂的解析与治理流程，对缺乏深厚数据与 AI 工程能力的企业而言，这是一道难以逾越的技术鸿沟。而解析质量的高低，直接决定了喂给 Agent 的上下文是"干净"还是"带毒"。

### 实时性与一致性难两全

Agent 往往需要在与业务实时联动的同时进行复杂分析——既要 OLTP 的低延迟点查，又要 OLAP 的复杂聚合，还要向量与全文的语义召回。传统架构靠多套系统 + ETL 来分担这些负载，结果是数据新鲜度差、一致性难保证、运维成本高。Agent 拿到的，常常是几个小时甚至几天前的"陈旧上下文"。

## 1.5 典型行业场景的落地难题

以下三个真实场景，展示了企业在迈向 Agent 化时，数据层面遇到的共性障碍。

### 报业传媒集团：内容生产 Agent 的"素材失忆症"

某成立近 30 年的报业传媒集团，看到了 GenAI 在内容生产上的强大能力，希望打造一个能嵌入采编工作流的内容生产 Agent。集团拥有海量媒体素材——历史报刊数字化文件、海量图片、音视频资料。但盘点后发现，这些素材散落在各种业务系统、硬盘、云网盘中，碎片化极为严重；编辑只能凭记忆和零星检索从中捞取极少量素材。即便勉强搭起 Demo，这个 Agent 也"记不住"哪些素材已被用过、哪些主题下有哪些可用资源，每次都要从头检索。要让 Agent 真正成为编辑的"第二大脑"，集团首先要解决的是多模态素材的统一治理、语义可检索、以及跨任务的记忆沉淀。

### 大型电子制造企业：质检 Agent 的"多模态盲区"

某年产值上百亿元的电子制造企业，拥有多家工厂、数十条产线，长期采集大量结构化（设备参数）、文档、图片与员工操作音视频数据。其中结构化数据已被 MES 系统较好承载，但工位摄像头采集的海量操作视频，目前只能靠人工抽查（覆盖率不足 5%）来判断工人是否规范操作。企业希望部署一个能 7×24 小时自动巡检的质检 Agent，但这要求把视频、IoT 时序、MES 结构化数据统一接入、实时解析、关联分析，并让 Agent 记住每条产线、每个工位的历史异常模式——这远超企业现有的数据与 AI 工程能力。

### 市级政府规划部门：招商研判 Agent 的"可信与时效困境"

某市级政府发展规划部门的招商人员，长期需要跟踪多个细分产业的市场动向与各地政策，结合本地产业数据按月输出研判报告。GenAI 工具的出现提升了一定效率，但面对行业研报、上市公司财报、工商注册信息等复杂多元数据，通用大模型的输出常常不够准确，尤其涉及本地产业的专属文件、政策与统计数据时更是力不从心。他们真正需要的，是一个能持续接入权威多源数据、对每条结论可溯源、且能跨月份积累产业知识的研判 Agent——而"可信"与"时效"恰恰是通用工具最难保证的。

## 1.6 小结

GenAI 的价值已被企业广泛认可，Agent 化更被视为下一个确定性的方向。但要真正跨越落地的"死亡鸿沟"，企业必须正视一个被长期低估的事实：**决定成败的不是模型，而是数据底座。**

Agent 时代对数据基础设施提出了与以往截然不同的要求——它不再是为人服务的 BI 报表系统，而是要成为能被 Agent 自主、实时、可信地消费的"数据与记忆中枢"。这个中枢必须同时具备：**多模态融合的统一接入与存储、AI 驱动的高质量解析与治理、向量与全文混合的语义检索、可演进可审计的 Agent 长期记忆、以及贯穿全链路的版本管理与合规保障。**

当前，行业亟需一套 **AI 原生、超融合、带版本与记忆、可被 Agent 即插即用** 的数据底座解决方案。这正是 MatrixOne Intelligence 要回答的问题。
